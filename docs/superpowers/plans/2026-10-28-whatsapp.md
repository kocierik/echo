# WhatsApp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Echo reads the user's private WhatsApp chats (held only in RAM, 7 days) and answers about them in Ask, voice requests and routines.

**Architecture:** A Node bridge (Baileys) links the user's number with a pairing code, keeps private-chat messages in RAM and serves them over an internal token-protected HTTP API. The backend proxies link/status/unlink for the app and offers a read-only `whatsapp` toolkit to the action agent. The app has Profile → WhatsApp.

**Tech Stack:** Node 22 + baileys 7.0.0-rc14 (ESM, node:test), FastAPI + httpx, Flutter.

**Spec:** docs/superpowers/specs/2026-10-28-whatsapp-design.md

## Global Constraints

- Bridge: port 3100, header `X-Bridge-Token` (env `WHATSAPP_BRIDGE_TOKEN`), data dir `/data/<user_id>`; RAM only for messages; 7 days, 20,000 messages per user.
- Private chats are `@s.whatsapp.net` and `@lid` jids; everything else ignored.
- Backend env: `WHATSAPP_BRIDGE_URL` (unset = feature off), `WHATSAPP_BRIDGE_TOKEN`.
- Tools: `WHATSAPP_LIST_CHATS`, `WHATSAPP_READ_CHAT`, toolkit `whatsapp`, both READ tier.
- Code, comments, commits in English; commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A server without `WHATSAPP_BRIDGE_URL`: no tools, no Profile row, chat and voice exactly as before.
- The bridge down or slow: the agent runs without WhatsApp; Profile says it cannot reach it.
- A message older than 7 days, a group message, a reaction: never stored.
- Unlink: the keys directory and the user's messages are gone.
- "Cosa mi ha scritto Marco?" reaches the agent (pre-check) and finds the chat by name.
