# Saved Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One generic kind of saved thing (title, details, fields, photo, place, its moment, its list) that Echo saves, updates, finds, sums and removes by chat and voice, shown in the app's Saved page and found again by memory answers.

**Architecture:** Two new tables (`saved_lists`, `saved_items`, migration 023) and a domain service `services/saved.py` without LLM calls. The action agent gets five own tools (`actions/saved_tools.py`), offered like the routine and to-do tools, routed by a new `"saved"` flag of the intent check. The phone's place comes from a new `get_location` device command answered through the existing command-result endpoint. Memory retrieval adds a "Saved things" section (without places for MCP). A REST router `/api/saved` serves the app's Saved page, a thing's page, move, remove and the late place. The app adds Saved models/API, a location service (geolocator + geocoding, permission asked on the first save with a place), the Saved and Saved-item screens, a Today row, and a chip in Ask.

**Tech Stack:** FastAPI, SQLAlchemy async, Postgres + pgvector, Redis; Flutter (iOS + Android), `geolocator`, `geocoding`, `url_launcher`.

**Spec:** `docs/superpowers/specs/2026-10-23-saved-design.md` (with "Answers to the builder check"); app structure from `docs/superpowers/specs/2026-10-22-app-tabs-redesign-design.md`.

## Global Constraints

- App UI copy in English only; the AI answers in the user's language (Italian and English texts server-side, as the other modules do).
- Migration 023, `down_revision = "022"`; `docs/schema.sql` and `tests/test_migrations.py` updated; no column added to an existing table.
- Places only on request: the position is read only by a save/update that asks for it; never stored anywhere but the thing; no distance computed on the server.
- MCP (outside assistants) sees saved things without address or coordinates.
- A saved thing's photo is `ON DELETE SET NULL`; "Remove from Saved" / "Found it" delete only the thing.
- Location permission asked only the first time a place is saved, never at start-up.
- Every test/analyze/build through the lock scripts, one at a time.
- Commit after each verified task, messages `feat(server): …` / `feat(mobile): …`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Saving the same thing twice ("il passaporto è nel cassetto" after "…nell'armadio") must update it, not add a second Passport → `save_item` same-title test (Task 2).
2. A "latest only" list (the car) keeps one thing; adding a photo to the car after parking must keep its place → `test_update_keeps_the_place` (Task 2) and `test_a_photo_after_parking_updates_the_car` (Task 6).
3. The phone never answers (app closed, background, permission refused) → the thing is saved without a place and the answer says so; the request does not hang more than 30 s → Task 3 tests.
4. Amounts written as text ("12,50", "€ 7.90") and mixed currencies must still sum, per currency → `test_sum_reads_text_amounts_per_currency` (Task 2).
5. A deleted photo or conversation must leave the saved thing readable (photo/conversation null) in the app and in retrieval → `test_deleting_the_photo_keeps_the_thing` (Task 2), detail endpoint test (Task 8).

### Task 2: The Saved service (no model calls)

**Files:** Create `backend/app/services/saved.py`, `backend/tests/test_saved_service.py`

**Interfaces — Produces (all flush, never commit):**
- `@dataclass Moment(request: str|None, source: str, conversation_id, segment_id)`.
- `async find_list(db, user_id, name) -> SavedList|None` (case-insensitive, trimmed).
- `async save_item(db, user_id, *, list_name, title, details=None, fields=None, people=None, photo_id=None, place=None, moment: Moment, latest_only=None, keep_days=None, embedding_service=None) -> tuple[SavedItem, bool]` (bool: created). Same title (case-insensitive) in the same list → `update_item` instead. New list created with `latest_only`/`keep_days` (ignored for an existing list). In a latest-only list a new thing deletes the others.
- `async update_item(db, item, *, title=None, details=None, fields=None, list_name=None, people=None, photo_id=None, place=None, embedding_service=None) -> SavedItem` — fields merged (a value `None` removes a key), place/photo replaced only when given, list moved by name (created if missing).
- `async match_people(db, user_id, names: list[str]) -> list[dict]` — names matched to person entities (case-insensitive first name or full name) → `{"name": entity.name, "id": str}` else `{"name": given, "id": None}`.
- `async find_items(db, user_id, *, query=None, list_name=None, date_from=None, date_to=None, limit=10, embedding_service=None) -> list[SavedItem]` — keyword words (≥3 chars) ILIKE on title, details, fields text, list name and people names; with an embedding service also cosine similarity > 0.35; newest first, the keyword hits first.
- `async sum_items(db, user_id, *, list_name=None, field="amount", date_from=None, date_to=None) -> dict` → `{"count": n, "totals": {"EUR": 184.3}, "list": name|None}`; amounts parsed by `parse_amount(value) -> (Decimal|None, currency|None)` ("12,50", "€ 7.90", 7.9, "1.234,50"); currency from `fields["currency"]`, the symbol, else "EUR".
- `async remove_item(db, item)`.
- `async expire_items(db, now) -> int` — deletes things older than their list's `keep_days`.
- `async load_items(db, user_id, ids) -> list[SavedItem]` with list.
- `describe_item(item, *, include_place=True) -> dict` (for the model: id, list, title, details, fields, saved_at local "%A %Y-%m-%d %H:%M", people names, address, photo text when given via `photo_text` attr) and `item_line(item, *, include_place=True) -> str` (one context line).
- `keep_note(lst) -> str|None` ("Kept until you save the next one, or for a week." style used by the app; the server returns `latest_only`/`keep_days`, the app writes the copy).

- [ ] Step 1: tests — save creates list+item with moment; same title updates (no duplicate); latest-only replaces others; `test_update_keeps_the_place`; move by `list_name`; fields merge and `None` removes; `match_people` with a known "Marco Rossi" for "Marco"; `find_items` by word in details, by list name, by date range; `test_sum_reads_text_amounts_per_currency`; `expire_items` deletes only past `keep_days`; `test_deleting_the_photo_keeps_the_thing`; `describe_item(include_place=False)` has no address/coords.
- [ ] Step 2: run → FAIL. Step 3: implement. Step 4: run → PASS.
- [ ] Step 5: commit `feat(server): the Saved service: save, update, find, sum, expire`.
